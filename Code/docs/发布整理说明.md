# GitHub 发布整理说明

> 发布目标：保留最新可运行代码、规划、评测入口和可复现 fixture；排除本机原始大数据、运行缓存和教学资料。
>
> 整理快照：2026-11-13（Asia/Shanghai）

## 已纳入发布包

- `agentic/`：协议、媒体标准化、质量门控、视觉/过程 Agent、Laya-JEV 路由、LangGraph 诊断图、RAG、HITL、RSI 和评测脚本。
- `config/`、`knowledge/`：模型 profile、worker 策略、版本化工艺知识规则。
- `data/evaluation/`：评测 schema、路由标注模板和 demo/行为 fixture；研究清单仍按 fail-closed 规则标记为不可声明。
- `docs/`：全局规划、执行计划、逐项核对、P0-G7 报告、PPT 大纲、实现日志和第三方清单。
- `report_assets/`：结构图、流程图和 PPT 所需的可复现素材；二进制 PPT/论文附件不纳入发布包。
- `model/`、`web_interface/`、`qt_interface/`：兼容入口和现代 Streamlit 工作台。
- `weights/`：现有基础视觉权重。它们约 67MB，是兼容视觉链路运行所需；新训练权重和中间 checkpoint 不提交。

## 明确排除的本地文件

| 路径 | 原因 | 重建方式 |
|---|---|---|
| `Code/data/v1/` | 原始 14 维过程时序数据和中间文件，体积大且包含本地数据 | 按 `build_process_manifest.py` 使用授权数据重建 |
| `Code/data/video/` | 原始巡检视频 | 使用本地授权视频运行 `demo_run.py` |
| `Code/data/火眼分类图片帧/` | 约 6,246 张图片帧，属于原始/弱标注素材 | 按 `build_visual_windows.py` 重建 manifest |
| `Code/runtime_data/`、根目录 `runtime_data/` | 运行记录、SQLite、浏览器缓存、截图和临时模型输出 | 运行测试、demo 和评测命令重新生成 |
| `baiduwangpan/`、`*.zip` | 教学参考和压缩归档，不是系统运行依赖 | 通过 `third_party_manifest.md` 记录借鉴范围 |
| `*.pptx`、`*.docx` | 汇报/论文二进制附件，避免仓库膨胀 | 发布 Markdown 大纲和 PNG/SVG 素材 |

这些规则只影响新提交，不会自动删除本地文件。当前历史中曾经提交过的旧视频和权重仍存在 Git 历史；若要彻底重写历史，需要单独进行有备份的 `git filter-repo` 操作，本次发布不做历史重写。
